# Problem_005 命题质量审查报告

审核稿，2026-11-03（北京时间）。题名：《校园小巴的高峰运行与调度》。本报告公开，仅列命题取舍、检验范围和误差，不给优选投入时刻、固定等候、控制阈值、具体策略轨迹或题目对照指标的数值答案。

## 1. 现实问题与证据边界

用户提供了一份问题征集答卷和深圳大学粤海、丽湖校区地图，并确认两校区均须研究。答卷只有一条，内容属于选题建议，没有客流或运营台账。因此，本题能据此确立研究矛盾，不能据此估计客流函数、满意度比例或现行车数。

主要矛盾是座位随车辆沿环线周转，乘客的目的地决定何处释放座位；乘降人数又改变停站和后续到达。总车数或全线平均满载率不能独立解释下游能否上车、乘客是否按时到达。消息延迟和交班使可执行安排受到进一步限制。

两张地图不是测绘或路权资料。题设的功能节点、单向环线、车队、容量、行时与管理规则全部明示为参考工况，没有冒充学校现行运营。原问卷及其身份字段、原地图均未进入公开目录。现场应用所需的路线确认和匿名补测保留在第四问，而不让必需的非公开后台成为比赛门槛。

## 2. 原创性、近邻与选题取舍

已检查仓库前四题，分别涉及水质输运、授粉、无源限速和积水屋盖，未重复其状态模型、数据或任务。官方近年目录、代表赛题、论文与评估资料的链接和实际阅读范围见 [research_review.md](research_review.md)。

直接近邻包括2025 ICM D的城市交通网络改进、2023 HiMCM B的车队电动化，以及2007 CUMCM B的公交路径查询。学术近邻更直接：公交串车、控车、限流和校园环线仿真已有成熟研究，Quek等2020年已研究大学校园系统。本题不把这些机制本身称为首次发现，也不能保证全球所有地方赛和培训资料没有同类题。

本题的独立命题工作是将有限期限、完整旅程、下游等待、只能使用已知信息、双校区验证和交班窗口放在同一运营过程内，明确区分优化指标、数据回放和可用观测。不是把城市最短路换成校园站名，也没有复用论文数据、干预公式或已有算例答案。

| 候选 | 可研究内容 | 取舍 |
|---|---|---|
| 固定环线的席位周转与因果调度 | 容量、目的站、停站反馈、队列和延迟 | 输入可在本科层面闭合，兼顾基础和深入路径；选用 |
| 双向、短环线与方向配置 | 潮汐需求、覆盖与车辆时空安排 | 缺少经确认的反向通行及掉头资料，不能凭示意图补出路权；不强制加入 |
| 小巴—中巴替代及完整司机排班 | 车型、成本、泊位与人员资源 | 未知项过多，容易制造支配解或拼盘；保留一项清楚的交班扩展 |

## 3. 数学对象与四问的依赖

状态至少涉及车辆位置/运行阶段、站内尚未分配队列、正在乘降者、在车者的目的站及已完成者。容量不是每天总座位数的简单相加，发车时刻也不是旅客到达时刻。改变方案后必须重算乘降和周转，不能继续使用旧方案的实际停站记录。

| 问题 | 数学研究重点 | 与后续的联系 |
|---|---|---|
| 第一问 | 建立车辆与旅客的动态守恒关系、容量约束及事件过程；辨别总供给和时空瓶颈，检验简化 | 为所有方案提供同一运行和计分环境 |
| 第二问 | 用规划样本确定有限维事前投入与回场等待，在固定资源下比较效果 | 形成不知验证未来的统一基准方案 |
| 第三问 | 在有限动作、局部即时量及延迟历史下设计因果规则，分析效率、在车耗时与各起点服务 | 检验事前方案在扰动中是否需要反馈，以及反馈代价 |
| 第四问 | 在回到0站的事件中满足完整交班窗口，保持旅客、车辆与驾驶员时空一致；提出实际检验 | 研究安排边界，并明确离线结果如何接受现场证伪 |

基础队伍可用事件模拟或小时间步过程，比较少量事前安排与简单阈值规则。较强队伍可建立时空容量必要条件、研究延误反馈、作多目标比较、用预测与滚动安排处理延迟，或给出可行域/策略边界。没有要求某一种优化、学习或预测算法。

难度不在CSV读写，而在目的站与座位释放、服务时间的内生变化、未完成人群的完整计入，以及允许信息下可执行的决策。给定服务和计分规则是为统一比较条件，没有给出完整状态递推、优化解或标准权重。

## 4. 参数、数据与公开检查

8份机器附件包含17个节点、9辆车、12个样本、7350条虚拟出行请求和2448条路段系数。全部为研究设定，没有真人行程；明确给出泊松块到达、起点权重、行程长度、期限、外生行时与扰动的生成机制和种子。

P1—P3用于规划，N/R/E固定用于验证。N/R/E在1800秒以前外部输入一致，之后分别保持正常、增加行时或追加客流。共同前缀是一项可查的因果必要条件，不是防止所有形式先知控制的技术保证。控制器还须提交输入说明和源程序。

| 公开检查项 | 结果及口径 |
|---|---|
| 输入 | 几何与单向连接、单位、初态、容量、OD、期限、完整时轴、配对情景及前缀均通过 |
| 重现 | 正式8文件逐字节一致并输出SHA-256；外部目录seed_offset=1重采样也通过，需求记录确实改变 |
| 损坏输入 | 14种损坏输入被拒绝 |
| 事前方案 | 2个合法格式及费用无关范围夹具通过；8种非法方案被拒绝。仅表示9车完整、归属与动作范围合规 |
| 日志与声明 | 第三、四问格式夹具通过；18种非法日志或声明被拒绝。只查声明、动作范围、交班声明和共同前缀，不证明物理、完整性或因果全域成立 |
| 交付 | 23个文件的白名单检查，题面附件引用、四页PDF文字及边界检查；不接纳原问卷、运行轨迹或完整参考求解器 |

生成程序没有读取优化结果，也不将推荐方案写成标签。公开完整回放数据不等于可以在动态决策中读取未来。新增样本可以检验对随机种子的过拟合，但仍不能替代真实观测。

## 5. 数值可解性与独立实现核对

命题阶段进行了两套分别编写的实现：另一AI代理采用离散事件队列，主执行者在未读取其实现前按一秒推进独立编写，然后交叉核对。所有时间与动作均为整数秒，比较口径相同；这不是两位人类专家认证，也不是实车验证。完整实现和方案轨迹仅用于本轮检验，未纳入公开交付，也未把仓库内目录视作保密位置。

| 检验 | 实际证据 |
|---|---|
| 完整过程 | 对12个正式样本跑对照；分别在每校区三份规划样本筛查有限事前候选及一小族因果规则，固定后验证N/R/E，含0/60/120秒延迟与交班 |
| 主批次 | 468次完整运行，包含对照和重复候选；只对应12个外部样本，不能把468次称为468份独立数据。主批次约43秒、峰值内存约22 MiB |
| 可行路径 | 两校区均找到有用的事前安排；简单反馈在不同校区不保证同时优于事前方案。既有改善也有代价，未预设反馈必胜或唯一最优 |
| 交班 | 已测对照和基础反馈均存在窗口内交班路径；不同工况下回到0站的可选次数不同，交班并非永不触发的装饰条件 |
| 不同实现对照 | 18组：两校区N/R/E的对照、带交班对照和一套非优化脚本动作。核对11415条逐人记录的上车/下车完成时刻及4358次车辆访问的到站、ready、离站、上下客、余载和交班标志 |
| 对照误差 | 最大时刻差0秒，逐人和逐访问差异0；按时人数、末期未完成、平均候车及容量峰值也相同 |
| 守恒与容量 | 逐事件或逐秒阶段检查站内、服务中、在车及完成状态；没有重复登乘、负人数或超载，人数守恒误差0 |
| 补充检验 | 60组过程：两种新种子的36组固定方案/反馈/带交班反馈、6组极端合法动作、12组匹配到站输入的不同OD、6组冻结规划平均停站的诊断性近似。回放37600条请求，94239次逐事件检查，守恒误差0；约6秒、峰值约23 MiB |
| 末期与机制 | 极端合法动作确会留下未完成者，全部进入截断候车及未完成统计；改变目的站与冻结停站可改变等待与周转。OD对照不以旧期限的按时率作纯容量归因，冻结停站不是符合原服务式的可实施策略 |
| 新样本 | 增加的12组交班过程可行，共同前缀检查全部通过；固定反馈在重采样中既有改善也有退化，未声称普遍支配事前方案 |
| 信息 | 基础控制器只接收允许即时量及按时间戳截取的历史，不传真实未来、case标签、候车者逐人OD或期限；两校区N/R/E共同前缀决策均一致 |

以上0秒误差指题设整数时间模型的实现一致性，不说明真实运行不存在误差。第三、四问的一组实际控制记录分别1382、1394行，通过公开声明与前缀检查，仍不把该PASS当作物理或因果全域证明。

有限候选筛查证明存在本科基本求解路径，不是全局优化或策略优越性的认证。事件实现很快不等于任何高维优化都能在同样时间完成；过于复杂的搜索应自行给出计算预算。

## 6. 已发现问题与修订

| 问题 | 修订 |
|---|---|
| 一条意见容易被写成全校调查事实 | 标明只有一条选题线索；不估计总体比例，不上传原表和身份字段 |
| 地图可能被误当真实米制路网 | 功能节点和连接明示为题设，图无比例及方位含义；不虚构当前通行和车数 |
| “最大载客流”容易退化为满载率或短途人次 | 同时保留完整旅程、期限、全部候车和末期未完成，以及分起点服务 |
| 使用预先录制停站时间会造成反事实不一致 | 只给不停车行时，服务时间随本次实际乘降数重新计算 |
| 停站新到者与同秒多车导致结果依程序容器顺序改变 | 冻结到站候选名单、明确先下后上、同秒旅客优先和车辆编号顺序 |
| 已选中但未完成上车者被漏算 | 标记服务中但候车计到完成上车，未完成服务保留在观察末期人数中 |
| 公共回放CSV可能被误用作实时未来输入 | 明确输入清单、延迟历史、禁止case查表、前缀测试及检查器的能力边界 |
| 本车下车人数和交班决定时点原先不够明确 | 将本次下车人数列为即时量；预留、控车和交班均在到站时一次决定，交班在ready执行，单行日志与实现一致 |
| 到站时可能提前记录未来离站 | 明确离站报告必须在实际发生后形成，预测值不能冒充已发生记录 |
| 交班可能把在车乘客清空或让车瞬移 | 固定0站，保留车内人，完整120秒落窗，交班与控车取最大额外停留，完成后改司机系数 |
| 所有设想同时加入会成为调度拼盘 | 不强制中巴、任意换向、短环线、购车和最大圈数，仅保留一项交班扩展 |

## 7. 难度、开放性与现实局限

建议96小时。基础模型用本科队列、离散过程和数值计算即可进入；较高水平的差异可来自容量分析、简化误差、因果性、策略复杂度和公平取舍。两校区要求分别验证，不能用一套调参结果冒充普适结论。没有唯一综合权重，也不要求每个指标同时改善。

现实局限必须保留：

- 当前没有已核准的现实运行网络、真实车队核载、完整起讫客流或连续行车记录。数值试算证明的是参考工况可研究，不能报告学校当前节时、准时率或所需车辆的真实结论。
- 忽略道路/站台阻塞、允许车辆交换顺序，冻结本次上车名单、采用批次服务，是为压低本科实现门槛的理想化。现场若不成立，应先修正模型，不能要求车辆执行不合法动作。
- 泊松块到达、行程长度及期限是设计假设。个体课表相关性、乘客改走步行、弃乘、收费和真实道路拥堵未由数据标定。
- 本车队列即时数和延迟到站报告是否可获得，须在试行前核实。信息成本及计数误差若不可忽略，应在实际建议中加入。
- 全部回放记录公开，检查声明与有限前缀不足以防止所有偷读未来。可复现程序和信息接口审查仍必要；没有将学术规则包装成安全隔离技术。
- 只有有限工况和候选，没有全局最优、连续不确定性保证或人类限时试赛结论。有限重采样不等于现场验证。

# 附件说明

附件使用两类信息：`cultivar_genotypes.csv` 的5条品种S型是公开的文献事实；其余数值是本题设计的模拟输入或独立试验记录，不是实际果园的观测数据。本文的“观察”“试验”均指题设中的模拟记录。没有整园坐果真值、预设最优方案或完整授粉求解器。

## 来源与计量

品种S型来自 Washington State University Tree Fruit 的 [Cross-compatibility of apple cultivars and pollinizers](https://treefruit.wsu.edu/article/cross-compatibility-of-apple-cultivars-and-pollinizers/)（2019，2024-02-13复核，2026-10-14访问）。逐项摘录 Gala、Golden Delicious、Mt. Blanc、Evereste 和 Frettingham 的5条事实，并另行编排为CSV；没有转载原表、图片或网页正文。原页面同时列出测定与综述论文。拼写采用不含商标符号的名称；C、D、E只作为本题授粉树使用。

参考事实只有S型；不能把附件中的当地花期、开花量、费用、移动和带粉参数归为WSU数据，也不能把它们外推为上述品种在所有地区的特性。涉及花粉延续和移动机制的背景参考 [Hung等，2023](https://doi.org/10.1002/eap.2917)；没有复制该论文数据、模型或程序。本题不要求查找外部参数。

长度用m，费用用元，时间用花期日序，花粉用粒。坐果试验的剂量为**相容花粉总粒数**，涵盖一朵花的五个柱头，不是每个柱头的数量，也不是已经萌发的花粉粒数。各品种活力按相同条件处理，萌发与早期果实保留的影响包含在独立剂量试验关系中。

## 果园、花期与访花口径

- `orchard.csv`：`tree_id`是固定树位；`row_id,column_id`从1开始，分别为1..8和1..18；`x_m,y_m`从(0,0)起，列向间距3m、行向间距5m；`current_cultivar_id`为前四行A、后四行B；`reference_flower_number`为原树位正常开花年份的参考花量。144株各有一个树位，没有额外可新增的树位。
- `cultivar_genotypes.csv`：`cultivar_id,cultivar_name,S_allele_1,S_allele_2,source_url`。两个S型视为该二倍体品种的不同等位型；一粒花粉以等概率携带其中一个。
- `cultivar_planning.csv`：`cultivar_id,role,flower_number_multiplier,replant_cost_yuan`。新株花量等于树位参考花量乘本品种系数；主栽A、B系数为1。费用一次性计入本题预算，C、D、E所结果实不计入主栽指标。研究的是改植后的正常开花年份，不比较树苗建立期或多年财务收益。
- `bloom_profiles.csv`：`day,cultivar_id,new_open_fraction`。每品种30行，共150行。比例表示该日新开放的花占该品种整季花量的份额，总和为1；不是“当日仍开放”的比例。每日开放花量由当天与前一天的新花组成。花在开放当日和次日均可提供花粉、接受花粉，此后不再参与授粉。比例是平均输入，允许用非整数期望花量计算。
- `visitation.csv`：`day,reference_bouts`。给定管理安排下的基准访花轮次，不要求参赛队预测天气或蜂群人口。每轮有50次单花访问（首访及后续49次移动）；同树换花计为不同访问。一天内使用该天的开花量和输入。首访概率按当天开放花量分配，初始无可供本园利用的花粉；考虑的访问均在园内，不引入园外相容花粉。花上有新花粉可采，供粉量在本题内不作为耗尽资源。同树内部可按花均匀访问进行基础分析，也可提出有依据的其他处理并检验影响。

人工授粉关系预测的是每朵花开放后第30日是否形成初期果。不同开放日的花分别计算，不把同一朵花的多次访问当作多朵花，也不重复计果。本题不研究后续疏果、果重、成熟期损失或最终收入。报告A、B总初期果数时，改植树位原来的主栽花量应移除；各行坐果率的分母是该行**保留主栽树**的整季花量，同时列明保留数量和花量，避免只比较改植后上升的比率。

## 独立试验

- `movement_trials.csv`：`bee_id,role,step,from_row,from_column,to_row,to_column`。等开花量样地的行株间距与果园相同；“等开花量”意指每树均有相同数量开放花，而不是不同日子的实园开花量。100个访花者，每个连续记录12次移动；`from`与前次`to`一致。树位相同表示在同树换花，不是没有访问。前80个访花者用于模型建立，后20个留出。位置记录不指定应如何把这种试验推广到开花不均匀的果园。
- `carryover_trials.csv`：`bee_id,role,recipient_order,total_deposited_grains,labelled_grains`。30个访花者，先带入纯标记苹果花粉，再连续访问20朵有未标记花粉的花；每一访问记录沉积在该花上的总粒数及其中的标记粒数。`recipient_order=1`是带标记后的第一次访问。标记只影响可追踪性，不改变活力或相容性；未标记的新花粉仍会被带走。该试验与整园首访时无可用花粉的边界条件不同，不能把它的初始装载当作所有园内访问的默认条件。前22个访花者标定，后8个留出。
- `fruit_set_trials.csv`：`batch_id,role,cultivar_id,compatible_grains,flowers,initial_fruits`。每个主栽品种4个独立批次，每批7种剂量、每剂量100朵花，共56行。使用完全相容花粉，一次施加已知粒数，之后隔绝额外授粉；记录各花开放后第30日的初期果数。前3批用于模型建立，第4批留出。同批共同条件、同访花者连续记录可能相关，数据划分按完整批次或完整访花者，不能随机拆散时间点充当独立验证。

`role=validation` 的记录不用于本次模型参数建立，应单独报告检查结果。合成程序公开，因而留出不是未知生成机制的盲测；作用是比较不同复杂度、推广假设和数据使用方式。较好拟合不等于唯一识别内部机制。

## 方案与情景

`rules.json` 记录题面统一参数：两预算6000/10000元、改植不超过12株且每行不超过2株、A和B各至少64株、增租0..3组、每组1500元、名义访花增幅为原轮次的20%。例如两组名义增幅为40%，不是连续乘1.2。第二问的“访花轮次加倍”是独立比较情形；第三、四问的可执行增租数量遵守最多3组。增加轮次不直接改变移动或带粉特性，这一推广假设需讨论。

`scenarios.csv` 含7个情景：`scenario_id`是名称；各`*_shift_days`表示该品种整体花期的日数偏移，负数提前、正数推后；第d日使用基准第d−shift日的新开花比例。平移不改变该品种整季花量，给定支撑和偏移均落在1..30日内；不可把移出数据范围的花默默丢弃。`low_activity_start_day,low_activity_end_day`为含端点的低活动日段，均为0表示没有；`bout_multiplier`只在该日段作用于访花轮次，其他日为1。增蜂名义倍数与情景倍数相乘。

情景不给定概率，也不表示真实气候频率。第四问中的方案在知晓实际情景前固定；可以在所列情景上使用不同有依据的可靠性评价，不要求预设的唯一风险权重。每组增蜂实际仅带来10%增幅的检验，应另外对所选方案计算，租金和数量不变。题目没有要求保证所有花、树或情景均达到固定坐果阈值。

## 生成与许可

`../scripts/generate_data.py` 使用Python标准库和种子20261014，重建全部10个机器可读文件。模拟花期用有限支撑的平滑曲线归一化；参考花量有小幅树位差异；移动试验采用随位移衰减的选择权重及同树项，访花者间有随机差异；标记沉积采用两类衰减时间尺度及粒数抽样；人工授粉使用有上限的剂量响应和整批差异。具体构造常量集中在脚本中，公开用于复现，不作为隐藏真值或指定解法。脚本不计算整园坐果、不选择配置、不提供优化输出。

在题目目录运行 `python3 scripts/generate_data.py` 可重建数值文件；`python3 scripts/check_data.py` 在临时目录重生成并核对，不改现有附件。数据字典为手写说明，不由造数器覆盖。

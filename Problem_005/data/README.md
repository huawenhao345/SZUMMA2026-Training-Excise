# 附件说明与数据字典

本题数值、简化环线、服务节点和运行规则均为**训练设定，非深圳大学现行运营数据**。Y、L分别参考用户地图中的粤海、丽湖校区功能分布，不表示已核准的现实线路或站名。两校区各自研究校内交通，不跨校区行驶、不共享车辆。

选题来自用户提供的一条去标识化校园交通建议；原答卷只有一条，不能用于估计客流、需求比例或总体满意度。原问卷含身份信息，未随题公开。两幅地图仅用于理解功能区，没有按图片像素估算距离或行时，也未转载原图。全部仿真数字由 `../scripts/make_inputs.py` 自主设定和确定性生成，不是从问卷提取的观测数据。

## 1. 文件与用途

八个机器可读附件均为UTF-8；CSV用逗号分隔、带表头，JSON为规则说明。

| 文件 | 内容 |
|---|---|
| `stops.csv` | 两校区共17个自定义服务节点及可控车标记 |
| `links.csv` | 单向环线相邻节点间的17条规定基础行时 |
| `vehicles.csv` | 9辆车的座位、司机行时系数与第四问交班窗口 |
| `cases.csv` | 12个规划或验证样本的索引与情景标签 |
| `passenger_requests.csv` | 各样本逐人到站、起终点及完成下车期限，供仿真回放与事后评分 |
| `link_factors.csv` | 各样本分时段路段行时系数，供仿真回放 |
| `baseline_plan.csv` | 题给对照方案的首次服务时刻与固定回场等候 |
| `rules.json` | 时间、乘降、动作、信息、交班、评价口径及生成机制 |

正式附件的 `seed_offset=0`，含7350条请求、2448条路段系数。每条请求是一人一次出行，不是问卷的一位受访者，也不是同一个人的多个可识别记录。

## 2. 时间、路网与车辆

时间统一为整数秒。`t=0` 是本次离线研究的开始，不对应现实某日钟点；观察至 `T=7200`。旅客到站时刻满足 `0<=arrival_s<5400`。初始各站无人候车，各车在0站场站空车待命。

各校区节点从0连续编号至 `n-1`，每车只沿 `0→1→…→n-1→0` 完整循环，每站必停。不得换向、绕行、短转；每名旅客只乘一车至目的站，不换乘、不改站、不弃乘。车辆可交换先后次序，本题不计算路段与站台阻塞；控车站有足够停靠空间。

### `stops.csv`

| 字段 | 含义 |
|---|---|
| `campus_id` | Y或L，仅表示本题两套独立场景 |
| `stop_id` | 校区内站号；Y有0—7站，L有0—8站 |
| `stop_name` | 自定义服务功能区名称，不是经校方确认的实际站名 |
| `control_allowed` | 1表示乘降关门后允许额外控车，0表示不允许；仅0、4站为1 |

### `links.csv`

| 字段 | 含义与单位 |
|---|---|
| `campus_id` | 所属校区 |
| `from_stop`、`to_stop` | 有向相邻站号，`to_stop=(from_stop+1) mod n` |
| `base_travel_s` | 不含乘降、控车与交班的规定基础路段行时，秒；不是地图测量值 |

车进入路段时，实际行时取 `ceil(base_travel_s × driver_factor × 当时该路段factor)`。途中越过300秒分段边界不重算。进入时刻若不小于7200秒，沿用该样本末段系数，便于登记越过观察终点的事件。司机系数和路段系数是外生条件，不得靠调高车速改善结果。

### `vehicles.csv`

| 字段 | 含义与单位 |
|---|---|
| `campus_id`、`bus_id` | Y1—Y5或L1—L4，车辆不可跨校区调用 |
| `seats` | 14个乘客座位，不含司机，不允许站立或超载 |
| `driver_factor_before` | 交班前行时乘数，无量纲；前三问始终用这一列 |
| `driver_factor_after` | 第四问完成交班后的行时乘数，无量纲 |
| `handover_start_s`、`handover_end_s` | 第四问允许的完整交班窗口，两端包含；不是到站窗口 |

### `baseline_plan.csv` 及自拟事前方案

| 字段 | 含义与单位 |
|---|---|
| `campus_id`、`bus_id` | 所属校区与车辆 |
| `first_service_s` | 首次驶入0站并开始服务的时刻，整数0—600秒；不是离站时刻 |
| `base_hold_s` | 首次以外每次回到0站，完成乘降关门后固定额外等候，整数0—60秒 |

对照方案为车辆编号依次相差120秒开始服务，固定回场等候为0；各站预留和动态控车均为0，跑完一圈继续运行。第二问只用P1—P3确定一个事前方案，固定用于本校区N/R/E，不允许每个验证情景换一份方案。

`check_plan.py` 接受与此CSV相同格式的自拟方案，要求两校区9辆车各出现且只出现一次。它只检查车辆归属、完整性和动作范围，不保证容量、交班或服务表现。

## 3. 旅客、乘降与容量

### `passenger_requests.csv`

| 字段 | 含义与单位 |
|---|---|
| `case_id` | 所属仿真样本；仅作回放索引，不是控制器输入 |
| `request_id` | 样本内唯一标识；与case_id组成唯一键；不是人员身份 |
| `arrival_s` | 到起点站加入候车队列的整数秒 |
| `origin_stop`、`destination_stop` | 起终点，互不相同，均属于本校区；只沿正向环线乘车 |
| `deadline_s` | 完成下车的期限，整数秒，包含等号；是生成的训练要求，不是真实课表或上课钟点 |

常规请求ID以R开头，活动追加请求以X开头。R前缀不代表雨情。相同校区N/R/E的常规请求ID和记录相同，避免同秒排序因情景改名而改变。

车辆到站时先处理下车，再决定本次上车。若下车人数为A、选中上车人数为B，乘降总用时为 `10+2A+3B` 秒；无人上下仍停10秒。A名旅客统一在 `到站+10+2A` 完成下车，B名旅客统一在 `到站+10+2A+3B` 完成上车。后一时刻称 `ready_s`，关门后方可离站或控车。

**候选名单在车辆到站瞬间冻结。** 本次只从当时已到站、尚未被其他车选中的队列取人，按到站先后、同秒按request_id字典序排列。选中者立即标记为服务中，不可被后车再次接纳；但在实际完成上车前仍计入其候车耗时。乘降及额外等候期间新到的旅客等下一车，不重开门。

同秒的旅客到站事件先于车辆到站事件；同秒多车到站按bus_id字典序分配，不增加额外站台阻塞。车辆到站下车后剩余在车人数为L，本站可分配候车人数为Q，预留r个空位时，本次接纳人数为 `B=min(Q,max(14-L-r,0))`。不得挑选目的地或期限，不得赶下在车者。r的范围是整数0—4；r=0表示有位即上。候车者少而自然空出的座位不构成违规。

### 完成与评价

- 按时率分母为该样本**全部请求**。完成下车时间不晚于deadline才按时；T末仍在站内、服务中或车内者均计不按时，并另报全部未完成出行人数。
- 截断候车耗时为 `min(完成上车时刻,T)-arrival_s`。尚未完成上车者均用T代入，即使已经被选中。报告全体均值、分起点95分位和最不利起点；不能只统计已登车者。
- 95分位统一采用次序统计量：n个样本升序排列，取第 `ceil(0.95n)` 个；无请求的起点记NA。
- 已完成上车者的乘车耗时从完成上车计至完成下车；未完成下车者截断到T，并单报其人数。未完成上车者不伪造乘车耗时，仍保留在全体候车与未完成出行统计中。控车和交班的车内耗时计入。
- 任何在T之后才完成的服务不能算成T之前已完成。需要核对站内、乘降服务中、在车和已完成的人数守恒，以及容量与旅客唯一性。

## 4. 情景与随机生成

### `cases.csv`

| 字段 | 含义 |
|---|---|
| `case_id` | 每校区P1、P2、P3、N、R、E，共12个样本，例如Y_P1、L_N |
| `campus_id` | Y或L |
| `role` | planning为规划样本，validation为验证样本 |
| `scenario` | normal、rain或event；标签只供回放和事后分组，不能作控制输入 |
| `paired_normal_case_id` | N/R/E对应的正常样本；规划样本为空 |
| `event_start_s` | R为1800、E为2100秒，其他为空 |
| `event_extra_passengers` | E追加人数Y为90、L为70，其他为0 |
| `event_origin_stop` | E起点Y为6、L为7，其他为空 |

### `link_factors.csv`

| 字段 | 含义与单位 |
|---|---|
| `case_id` | 回放样本 |
| `block_start_s`、`block_end_s` | 300秒区间，左闭右开，从0无缝覆盖到7200 |
| `from_stop`、`to_stop` | 校区有向路段 |
| `factor` | 无量纲路段行时乘数，保留6位小数 |

P1—P3相互独立抽样。每校区N/R/E共享同一个正常潜在样本：R保留全部原需求，只在不早于1800秒的路段系数乘1.25；E保留正常系数和全部正常请求，另在[2100,2400)加入指定起点的活动请求，正向乘2或3站的概率各1/2。N/R/E在1800秒以前的请求与路段系数完全相同，第三、四问策略在这一共同前缀内也必须给出相同决策。

常规需求按18个300秒块生成。每块到站人数为泊松变量，均值为“基础每分钟强度×5×块倍率”；块内每人独立取均匀整数到站秒，允许同秒到站。Y基础强度7.2人/分钟，L为5.4。18个倍率依次为：

```text
0.7,1.1,1.8,1.6,1.2,0.6,0.7,1.2,1.8,1.5,0.9,0.5,0.7,1.2,1.7,1.2,0.5,0.3
```

通常时段的起点概率权重：

```text
Y: 0.32,0.14,0.17,0.05,0.06,0.05,0.08,0.13
L: 0.33,0.11,0.06,0.08,0.12,0.05,0.08,0.09,0.08
```

在[1800,3600)秒，将上述向量沿环线正向旋转Y为4站、L为5站。原0/1源点及其旋转后对应源点，乘4/5/2站的概率为0.55/0.25/0.20；其他源点乘1/2/3站概率为0.4/0.4/0.2。OD基础行时为正向沿途基础路段行时之和。期限按

```text
deadline = arrival + ceil(0.96*OD基础行时) + 10*(乘坐站数+1) + 5 + slack
```

生成；slack为240/360/480/600秒，概率为0.1/0.3/0.4/0.2。期限已经预留后续步行，不是测量到的实际课表。正常路段系数为各段、各边独立的0.95—1.08均匀扰动，保留6位小数；R的乘数作用后也保留6位小数。

生成使用Python标准库`random.Random`和Knuth乘积法泊松数。校园基数Y为101、L为201。规划Pj使用`基数+j+100003*seed_offset`，验证共享`基数+10+100003*seed_offset`；再乘100加1/2/3，分别作为旅客、路段和活动追加的随机种子。实际种子完整列于`rules.json`的`random_generation.seeds`。没有用优化结果反向生成数据，也没有将参考方案隐藏为标签。

## 5. 动作、信息与第四问交班

每次到站可以决定整数预留r=0—4。只有0、4站在完成乘降、关门后允许额外控车u=0—90秒，期间不开门，其他站u=0。第三、四问的动态控车取代第二问固定回场等候，不叠加成150秒。

调度在车辆到站时可立即知道当前时间、本车ID、本站、本车本次下车人数、本车下车后余载和本站当前可分配候车人数。本次下车人数由司机到站即知，可用于计算ready，不含未来数据。其他全网信息须延迟δ秒，默认δ=60，另检验0和120。可用历史报告仅包含到离站时刻、上下客人数、总载客量，以及**过去车辆到站时观察到的可分配候车人数**。后者不是各站实时快照；没有车辆到站期间的新队列不能直接看见。除事前已知参数和完整初态外，只能使用时间戳不大于`t-δ`的已发生报告。到站报告在到站时形成，离站报告须在实际离站后形成；不能在到站时提前把预计离站记录加入历史，也不能把预测的未来状态冒充已观测数据。δ=0时，同秒也仅允许读取本次决定前已处理的报告。

截止时间与OD供仿真环境安排下车及评分，策略不能直接读取未登车者逐人OD或期限，也不能通过完整请求文件、case_id、种子或未来路段文件偷读未来真值。车辆已上车者的目的地可由仿真内部用于下车处理，但不属于题设允许的控制器输入清单。历史P样本可用于研究时段需求与OD规律；已知规律可预测，不能将未来实现当成当前观测。

第四问才启用交班。车b（按0起算）窗口为`[1800+120b,3600+120b]`秒。预留、控车和是否交班均在车辆到站t一次决定，仅0站可选交班；若选择，则在本次乘降完成ready立即开始，须有`窗口起点<=ready<=窗口终点-120`。交班120秒后完成并改用after系数。每车须在本车窗口内完成一次；未完成者过窗后不能继续按原司机工作。车内旅客保持在车，接班人员分别分配给各车，不增加共享司机稀缺约束。

控车与交班可重叠，总额外停留为`max(u,120)`，不相加；下一路段须等交班完成后才能进入。交班窗口和before/after系数事前可知，交班决定同样不得使用未来真值。

## 6. 控制日志与声明检查

`check_action_log.py`只检查声明、动作范围和1800秒前的共同前缀，是必要条件检查。它不重新仿真，不核对日志是否完整真实，不证明容量、物理可行性、运行表现或源程序从未偷读未来。队伍仍须提供输入清单、伪代码或程序，接受因果性审查。

控制日志为CSV，每个δ、每个策略单独提交一份，包含两校区全部六个N/R/E；各工况内按`time_s,bus_id`排序。每次车辆到站都应记录，包括动作全为零的到站。

| 字段 | 含义 |
|---|---|
| `case_id` | 仅回放与核对所用的样本索引 |
| `event_index` | 样本内非负、唯一、递增的决策事件序号，不能因情景改名而改变共同前缀编号 |
| `time_s` | 本次车辆到站、一次决定预留、控车和是否交班的整数秒 |
| `bus_id`、`stop_id` | 车辆及当前站点 |
| `ready_s` | 本次乘降完成时刻，不含额外控车或交班 |
| `reserve_seats`、`extra_hold_s` | 本次预留与关门后额外控车，整数座位/秒 |
| `handover` | 第三问必须为0；第四问本次在ready立即开始交班时为1，否则0 |
| `delayed_cutoff_s` | 声明本次读取全网历史的最大时间戳，不得大于`time_s-δ`；开局可为负，已知完整初态另行处理 |

声明JSON须且只含以下字段；下面是格式示例，不提供调度动作或参考策略。

```json
{
  "schema_version": 1,
  "task": 3,
  "information_delay_s": 60,
  "controller_name": "参赛队自拟控制器名称",
  "instant_fields": ["time_s", "bus_id", "stop_id", "alighting_count", "onboard_after_alighting", "eligible_queue_count"],
  "delayed_fields": ["arrival_departure_times", "boarding_alighting_counts", "onboard_totals", "queue_seen_at_past_arrivals"],
  "planning_cases": ["Y_P1", "Y_P2", "Y_P3", "L_P1", "L_P2", "L_P3"],
  "uses_case_id": false,
  "uses_future_truth": false,
  "uses_waiting_individual_od_or_deadline": false,
  "logs_all_arrival_decisions": true
}
```

`instant_fields`、`delayed_fields`可以是允许集合的子集。声明不是行为证据；即使共同前缀通过，也不能排除策略在其他时段偷读真值。第四问检查器要求声明日志中每车在各样本完成一次合法交班；研究不合格对照时，可以保留FAIL结果并说明，不能修改记录伪装通过。

## 7. 重现与检查命令

在`Problem_005/`目录执行：

```bash
python scripts/make_inputs.py
python scripts/check_inputs.py
python scripts/check_plan.py data/baseline_plan.csv
python scripts/check_action_log.py /path/to/actions.csv --declaration /path/to/declaration.json
```

检查脚本仅用Python标准库。`check_inputs.py`检查站点/环线、座位与班表、OD与期限、全路段时轴、N/R/E关系及共同前缀，再与确定性重生成逐字节比较并输出SHA-256。

额外重采样必须写入其他目录，不能覆盖正式附件：

```bash
python scripts/make_inputs.py --seed-offset 1 --output /path/to/extra_inputs
python scripts/check_inputs.py --seed-offset 1 --data-dir /path/to/extra_inputs
```

重采样改变旅客和路段扰动，不改变车辆、网络和动作范围。它可用于检验过拟合或策略稳定性，不改变正式评价样本；不得看完验证表现再为每个样本调参。正式输入逐字节重现与完整源程序均公开，完整参考求解器、优化组合和策略轨迹不在公开附件中。


## 8. 转向实际运营时的最低资料

本题计算可完全使用给定工况。若进一步形成真实排班建议，两校区须各自确认现行站序与通行方向、车辆实际核载与可用时段、允许控车/乘车规则、司机交接条件及信息来源，不能用参考模型直接代入。

最低观测字段包括校区、观测日期与时段、站点、车辆匿名编号、实际到离站时刻、上下客人数、可见队列人数及在车总人数；注明天气/活动和计数缺失。目的站结构可另用自愿、匿名的起讫组合计数补充，单站上车总数不能唯一还原OD。只需汇总旅程，不收姓名、手机或可识别个人轨迹。采多少站、多少天、如何同步、如何分训练与验证、怎样比较试运行前后，是第四问需论证的内容，不能仅用全校平均值代替。

# Problem_002 命题质量报告

题目：**苹果园的授粉安排**。版本：2026-10-14（北京时间），用户审核通过后的提交版。题面、数据和审查材料先供用户审核，用户已确认并授权创建PR。评分是命题执行者的内部自审，不冒充第二位评审或竞赛组委会认证。独立数值核验采用另外编写的计算路径，报告不提供完整参考解答或关键策略结果。

## 1. 现实问题与原创性

主栽品种连片种植便于管理，授粉却同时依赖遗传相容、花期、访花移动和先前携带的花粉。增加访花量、改变供粉源的空间位置和改变花期覆盖并非必然等效；改植又损失主栽树位。这些因素产生了可以分析的替代、互补与风险权衡。

遗传相容信息来源于WSU推广资料。花粉延续和移动对授粉效果的作用已存在科学研究，本题不声称机制创新。原创性在于独立构造的果园、不同时间与空间证据、有限改植及增蜂预算、初期坐果的非线性和事先固定方案的情景比较。

近十年官方赛题筛查沿用并复核上一题调研。本轮重点读取2025 ICM E、2022 HiMCM A及2021 MCM A官方背景，明确最接近的蜂群题关注人口动态与需蜂数，而本题固定访花者类型，研究有效供粉和树位安排。Hung等2023论文研究蜂类和既定布局，本题未复制其模型、数据或程序。查重是有界检索，不是全球无近邻的证明。详见 [调研记录](research_review.md)。

仓库已有第一题研究低用水管网。本题不复用其输运方程、监测反馈任务或数据，仅沿用文件组织与编译检查做法。全部新增文件在 `Problem_002/`，第一题和其他既有内容不改动。

## 2. 四问的数学结构与可行方向

| 问题 | 核心研究 | 本科基础路径与边界 | 深入研究空间 |
|---|---|---|---|
| 1 | 相容概率、试验关系、带粉来源与后续坐果 | 根据题给机制建立概率与数量模型，用完整访花者、完整批次留出检验；等花量试验不能确定任意花量条件的行为规律 | 参数相关性、来源过程、推广假设、剂量非线性与不同层次的随机性 |
| 2 | 同布局中的花期、位置和有效供粉差异 | 用第一问模型计算两种主栽与各行表现；访花轮次加倍作为比较情形 | 什么时候更多访问有效，什么时候效果受供粉或时间重合限制；结果的模型误差 |
| 3 | 原树位损失、品种、位置与蜂群数量的联合安排 | 合法简单配置与有限候选改进；比较两预算的结果及空间取舍，不要求全局最优 | 非线性相互作用、总体与均匀性、组合求解、误差如何改变方案排序 |
| 4 | 花期前固定决策的可靠性 | 在七情景和增蜂效应下降时复核同一方案，选择有依据的风险评价 | 情景相关性、结构与参数不确定性、外推边界和补充调查价值 |

后续问题实际使用前一问的模型：改植改变花量、品种和访花机会，花期情景又改变可用供粉和受粉窗口。没有把估计、优化和验证拼成独立的算法作业。题面不预置指标权重或概率分布，也没有要求唯一配置、固定坐果阈值或最优性证明。

数学难度并不来自遗传学专业知识：S型判别规则直接给定。关键是把花间移动、来源、重复访花和初期坐果连接起来，并决定什么近似仍然有效。适合96小时的三人本科训练；72小时训练可采用较简洁模型和有限方案比较。

## 3. 数据与来源检查

机器附件为9个CSV、1个JSON，另有数据字典。CSV共 **2197行**，其中 **5条有来源的遗传型事实、2192条模拟记录**。原果园144个树位、两主栽各72株，参考花量合计215292朵。没有提供整园坐果真值、标准方案或评分数值答案。

三组独立试验包含：100个访花者的1200次位置转移；30个访花者的600次标记沉积；两主栽品种各4批的56条人工授粉记录。独立分组标定/留出，不把同访花者连续记录或同批条件当作独立重复。生成机制公开，留出是模型比较，不是未知造数机制的盲测。

`check_data.py` 已核查字段、品种、几何、完整时轴、整季开花比例、访花记录连贯性、花粉计数上下界、花/果数量、分组标签、情景平移守恒、预算与控制规则，并在临时目录重生成全部10个机器文件；逐字节及SHA-256一致。4个故意损坏的数据副本均被拒绝。`check_plan.py` 接受合法方案，拒绝主栽互换、每行超限、增蜂超限与超预算4种方案。副本和试算方案均不入公开目录。

模拟参数不冒充实际品种在任一地区的花期、收费或访花特性。公开生成器只造外部输入、试验和情景，没有整园授粉求解器或优化输出。文献事实、原创编排、合成记录与第三方图文许可分别说明，未转载原图、原表或实验数据。

## 4. 可解性及独立数值核验

完整原型仅在本次临时工作区验证，没有上传完整参考解答或基准策略。公开这里只给非答案性证据。

在最终附件上，标记沉积的留出比例RMSE约 **0.062**；人工授粉两主栽的留出坐果比例RMSE约 **0.035、0.070**。这些结果提供可检验的基础路径，不证明内部机制唯一，也没有把试验抽样波动当成模型的确定误差。等花量试验对非均匀花量响应的支持有限，第四问已保留推广误差的讨论。

基础计算筛查了两个预算、0至3组增蜂下的 **8类合法方案**，另有原布局、单一措施和访花轮次加倍对照。最终数据重新计算了全部方案在七情景及增蜂实际增幅下降时的表现。名义收益与情景可靠性并非相同排序，改植损失和增蜂开支形成实际取舍；任务既非全部无效，也非一项措施即可使所有花达到同一结果。未公开具体最优候选或果数。

发现初稿只保留平均带粉比例的近似存在系统偏差后，另外建立了保留访花位置与花粉来源相关性的计算，并用独立随机访花程序回放核查。4类受检运行各使用4个独立种子、每天2000条路径；两种计算的总量差异约 **0.005%—0.40%**，与抽样波动量级相符。没有将原平均近似直接当作标准答案。

进一步提高确定性计算精度，受检总量变化小于 **5×10⁻⁷**；移动概率归一误差小于 **9×10⁻¹⁵**。这只是实现与离散计算证据，不能解释为果园预测的现实精度。零访花、只有不相容同一克隆的极限情形正确给出零；独立推导的“两树、两次访花”解析情形与程序绝对差约 **8×10⁻¹⁴**。

另外完成 **15项**花量响应和携带过程参数的结构/参数变化检查：输出有界、方案仍满足控制规则，但效果和选择需要条件性解释。花朵有效窗口按开放日和次日累计，每朵只计一次初期果；改植树位不继续贡献原主栽果数。

计算资源实测：初次8类有限候选方案搜索约 **6.4分钟**；四类随机回放约 **34秒**，另一路径的精度与情景核验约 **21秒**；峰值内存不超过 **63 MiB**。环境为Python 3.12、NumPy 2.3.5、SciPy 1.17.0、Linux CPU容器，单线程限制。只证明一条基础路径在常见本科设备上可行，不保证任意算法同样耗时。公开生成、附件与方案检查仅依赖Python标准库。

## 5. 实际发现与修订

| 问题 | 修订 |
|---|---|
| 花期提前后有少量花移出观察窗口 | 调整有限支撑，逐情景检查整季花量守恒；使用修订后附件复算所有方案，不把截断当作少开花 |
| 初期坐果试验的粒数名称暗示“已萌发” | 改为相容花粉总粒数，统一五柱头、活力和后续隔绝授粉口径 |
| 主栽保留60株在总改植12株下冗余 | 保留约束改为各64株，与全园/每行限制共同检查 |
| 平均带粉近似未保留来源与位置的相关性 | 用独立程序复核并修正预测路径；不通过给旧近似高分绕过差异 |
| 改植后只看坐果率可能掩盖主栽花量损失 | 同时比较果数、保留株数与各行比例，明确移除被改植的原花量 |
| 人工授粉与实园重复访问口径不一致 | 给出同花两日窗口、单花计果、每轮50次与首访边界，区分试验初始装载 |
| 用情景真实状态反向挑方案可能乐观 | 第四问的安排在花期前固定，各情景复核同一安排，不提前按已知情景调换树位 |
| 表格文件名溢出、附件标题孤立 | 文件名分行，附件单独起页；两遍编译检查与全页目视 |
| 题面像建模流程或审查手册 | 去掉环节性标题和重复评价措辞，保留自然背景、条件和四问，详细说明移至附件 |

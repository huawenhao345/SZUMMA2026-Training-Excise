# 独立选题与科学合理性审查

审查日期：2026-10-14（北京时间）。本文件是公开命题审查材料，不是参考解答。它记录独立审查提出的质疑、资料核查结果和终稿必须满足的边界，不提供完整模型、求解步骤、参数估计结果或网络策略结果。

## 1. 审查状态与结论范围

本文件包含候选题比较、真实机制核查、数学结构预审、首轮题面复核及最终独立验收。采用“保持压力的低用水片区”场景，以余氯、输运历史、水箱混合、冲洗与有限观测之间的关系组织任务。预审阶段不评分，不以选题潜力代替可解性证据；最终验收与评分见第 10 节。

独立审查支持继续发展这一候选：节水与既有供水设施之间存在真实运行矛盾，输运和混合记忆使问题超过静态水量计算；同时，预测与控制的可信度受到数据支持范围的限制。此判断不是对真实供水系统安全性或实际冲洗效果的认证。

## 2. 候选比较与取舍

| 候选 | 现实与数据基础 | 可形成的数学研究重点 | 独立审查意见 |
|---|---|---|---|
| 保持压力的低用水片区末梢水质管理 | EPA 明确指出低流量节水措施会给按较高流量设计的设施带来水质挑战，并提供水龄管理、冲洗和水箱评估资料 | 输运历史与混合分布、可辨识边界、共享设施的控制影响、观测对决策的价值 | 优先发展，但必须闭合初态、反应机制、温度和低流外推假设；不得将余氯指标等同于完整健康风险 |
| 配网变压器热记忆下的充电调度 | 有成熟热老化研究；Caltech ACN-Data 提供真实充电会话数据，但其 API 需要注册 | 动态热约束、累计老化、随机到离时间与调度 | 可解性较好，但智能充电和变压器寿命研究已十分丰富；若仅组合标准热模型与优化，原创训练价值不足 |
| 热浪期间公共避暑空间容量配置 | 地理、设施与人口数据较容易获得，但真实使用和健康效益数据不足 | 容量与时空可达性、行为响应、资源配置公平性 | 易退化为常规设施选址；不得未经证据将新增容量直接转换为死亡或患病减少 |

取舍依据分别见 EPA 低流量研究 [R1]、ACN-Data 官方说明 [R8] 和 UKHSA 综述 [R9]。比较不意味着另两个方向不适合作为赛题，而是认为本次条件下供水方向更适合形成相互依赖、需要理论与计算共同支撑的任务。

## 3. 已核查的真实机制

1. **低需求可能增加水龄。** 低用水、过大的管道或储水设施、末梢和流通不良均可增加水在系统中的停留时间。EPA 将这些情况列为水龄管理对象，并同时强调压力要求 [R1–R2]。
2. **余氯衰减涉及多种反应。** 体相反应与管壁反应并非同一机制。管材、管龄、沉积物以及水质条件会影响反应；瓶试结果不能自动代表管壁耗氯 [R2、R5–R6]。
3. **混合方式影响水质与可观测性。** 实际水箱可能存在短路、慢交换区域及分层。EPA 的评估协议和 EPANET 说明均将混合状态作为运行分析内容 [R4–R5]。
4. **低速换水与管壁清洗不能混同。** 冲洗可以置换滞留水和恢复消毒剂余量，但是否清除沉积物、生物膜或结垢取决于技术和速度。某些冲洗还可能扰动沉积物 [R3]。
5. **监测点和采样过程必须匹配研究对象。** 从建筑水龙头取得样本时，样本可能反映建筑内部管道而非配水干管。EPA 的代表性采样指导要求明确相应取样过程 [R10]。训练附件应明确监测的是指定设施或管段的出水，不能省略这一位置定义。

上述依据支持问题背景与理想化机制选择，不提供本附件参数的实测来源。若附件采用合成数据，必须逐项标识，不能把引用的真实研究写成附件数据来源。

## 4. 原创性边界与近邻研究

余氯预测、水龄管理、水箱混合、传感器布点和冲洗优化均已有长期研究。EPANET 本身已包含多种混合方式、非反应示踪、余氯反应和水龄分析 [R5]；2022 年研究已讨论实际网络中的在线余氯模型校准与监督 [R7]；EPA Water Security Toolkit 也包含监测与冲洗响应相关功能 [R11]。因此，不将这些单项机制或“监测与冲洗联动”描述为首次提出。

本题可主张的原创性是：围绕一个独立构造的低用水训练场景，使用相互制约的证据和运行约束，要求参赛者辨别数据能够支持什么、检验简化指标、评估共享输运历史下的决策，并讨论新增观测的价值。原创模拟题不等于新科学理论，也不能靠换地名、修改管网规模或更换算法名称证明原创。

本文件的机制与文献核查不能代替历年竞赛题全文比对；竞赛题和仓库既有题目的重复检查须在总审查报告中另行记录。若只完成题名或摘要筛查，应明确该范围，不能声称绝无相似题目。

## 5. 独立质疑、修订方向与终稿验收边界

| 审查提出的问题 | 当前命题取向或修订方向 | 终稿与验证必须检查的内容 |
|---|---|---|
| 间歇停压会引入污染入侵、水锤、空气等未覆盖机制 | 采用保持压力的低需求场景 | 题面须明确理想化供水能力保证与流量约束的含义；不能把流量上限当作已求解的压力场 |
| 固定水位设施不当然具有水量调蓄功能 | 使用固定水位在线混合设施的抽象 | 统一设施名称；进出水量平衡与运行规则必须一致 |
| 入口温度变化不能无说明地代表全网同步水温 | 明确稳定水温、规定水温工况或温度不确定性 | 温度定义、瓶试覆盖范围和预测假设一致；不暗中要求选手补做完整热传输问题 |
| 瓶试不能识别未知壁耗 | 明确忽略壁耗的适用边界，或另给材料试验/反应区间 | 若保留壁耗，须给足数据或允许区间研究；不能让不可估参数成为唯一答案的前提 |
| 把平均水龄直接替代完整输运与反应信息可能产生错误 | 将简化指标的充分性作为可检验问题 | 不预设误差方向，不预设长尾一定降低平均出口余氯；要求结论附带适用条件 |
| 箱内体积平均龄、出口水样平均龄和用户取水龄不是可随意互换的概念 | 固定水龄对象和起算边界 | 所有任务、数据字典和结果要求使用一致定义 |
| 很低流量下理想塞流并非精确物理描述 | 使用可解释的工程运输近似，并保留局限讨论 | 根据流量与尺度检查近似；不能声称低流条件天然满足充分混合或无弥散 |
| 常流示踪不足以确定任意低流或停流下的混合规律 | 使用多个工况与留出检验，或把外推规律纳入不确定性 | 记录长度覆盖可见尾部；明确没有观察到慢尾不等于不存在慢区 |
| 有限预热可能无法消除慢区或停流段初态影响 | 给出可使用的初态或明确初态不确定性 | 不以未经验证的“已充分预热”替代初边值闭合；检查初态对预测结论的影响 |
| 冲洗可能被错误建模为即时重置，或只按静态补流量计效益 | 保留历史输运、共享设施容量与运行状态 | 检查质量与水量守恒、响应延迟、过渡期以及至少一个可行运行方案 |
| 总体均值可能掩盖少量用户的长期不达标 | 同时关注用户需求加权表现与末梢表现 | 冲洗排水不得充当用户供水需求；公平性与最长不达标时段等指标须明确 |
| 反馈性能可能因读取未来数据或同模型自证而被夸大 | 控制器只用已获得观测，使用独立扰动情景比较 | 明确观测误差、延迟与可用信息；模型内验证不得表述为真实供水健康效益 |
| 公开网络观测生成器可能等同公开前向求解器 | 生成器以独立试验和外部输入附件为范围 | 不包含全网余氯答案、优化策略或最终结果；若生成内容变化，必须重新审查泄漏边界 |

以上修订方向应在正式题面与附件就绪后逐项确认。表格记录审查要求，不提前宣称实现或数值验证已通过。

## 6. 可解性与区分度的审查要求

第一部分必须允许参赛者给出“现有数据不足以唯一确定某项机制”的合理结论，不能暗藏必须恢复唯一参数的要求。后续预测应在明确假设下可计算，且不以无法获得的观测为前提。冲洗任务应产生真实耗水与水质权衡；若全部约束过松或全部方案不可行，都应修订数据。第四部分应控制范围，允许简单、可解释的布点和反馈方案，不要求一般系统的最优自适应控制证明。

区分度应来自模型解释、证据使用、守恒推导、近似误差、实验设计和决策可靠性。采用更复杂的软件或更多算法，不应自动成为高质量建模的证据。

正式验收至少需要数据复现、单位与时序一致性、瓶试与示踪范围检查、基本守恒情形、低/零流量行为、离散精度检查和可行策略试算。这里只记录应检验的性质，不公布基准模型、数值答案或策略。

## 8. 首轮正式题面复核

本节保留首轮审稿时的发现与待办记录；对应问题的最终修订和验收状态见第 9、10 节。

已对首轮 `problem.tex`、CSV、运行规则 JSON 和生成程序进行独立阅读。该版本已明确固定水位与进出水量平衡、保压能力抽象、统一设施水温、管道有效附加反应率、水龄初态与出口定义，以及需求加权指标中不计排放水的规则。四项任务能形成“证据支持范围—无排放预测—有限水量决策—监测与反馈检验”的依赖链；不要求证明一般系统的全局最优策略，允许透明简易方案作为对照。

本轮附件结构阅读和独立抽查确认：拓扑为十个节点与九个管段；输入时轴包含三天历史及七天决策期；瓶试留出按独立平行瓶划分；示踪缺测采用空值和标记，而非以零填补；管段几何容积与记录值的舍入一致。各末端名义需求为正，初态不会依赖未提供的历史重建。此类结构检查不能证明水质任务具有非平凡性。

仍需注意以下事项：

- 示踪工况并未覆盖每一种无排放和允许排放下的流量。最低需求和较强排放仍存在工况外推，终稿必须保留模型不确定性与外推边界，不能以留出检验代替全运行范围验证。
- 公开可复现的孤立试验生成程序必然使实验生成机制可读。第一问应重在模型的证据支持、比较和推广，不应将恢复已公开的生成参数当作核心挑战。直接在数据说明中列出闭式响应也会降低基础辨识部分的探索空间；即使保留，也必须在难度和泄漏风险评估中承认这一影响。
- 新增监测点的首次采样、最后一次采样以及一小时到达延迟应明确到具体时刻。当前实测入口与水温、名义未来工况和未知未来扰动必须区分，避免控制器意外读取未来情景。
- 基础方案与闭环方案必须采用一致的容量检查、扰动情景和预算口径；闭环检验模型至少在一项混合或反应假设上与设计模型不同的要求，有助于避免完全同模型自证，但仍不能证明现场有效。
- 数据许可与代码许可应在实际文件中落地。引用官方说明不等于复制官方资料许可；本附件是原创合成数据，不应宣称实验得到 EPA 认证或背书。
- 数值试算已触发对耗氯强度与任务非平凡性的再次检查。在确认无排放对照、预算权衡和稳健性试验具有实际区分度之前，不完成评分或验收。

四项任务对常见三人本科队伍具有较高负担，但第一问、输运实现与计算实验可以分工；第三问只要求可执行方案及对照，第四问允许简洁反馈规则，而非强制复杂控制算法。若评阅要求暗中加入完整联合辨识、全局最优解或充分概率风险估计，将超过题面授权的研究范围和建议时长。

## 9. 最终修订与复验记录

最终题面及附件已完成以下修订，并经过独立复查：

1. **修复数值任务空洞。** 初稿试算发现无额外排放即可满足名义目标，不能支持有区分度的预算决策。命题方退回合成数据设计，在保持服务目标不变的前提下调整为公开标识的高反应性水质，并重新生成、拟合及试算。审查确认这一参数构造不被包装成真实机构实验；公开附件仍不包含网络真值或预设最优操作。
2. **减少不必要的形式提示。** 数据说明移除了孤立实验的闭式响应与精确构造参数，保留机制、假设和公开生成程序指向；正式任务改为比较模型复杂度、证据支持与外推表现。生成机制仍可公开阅读，题面和 README 已明确留出标签不构成保密盲测。
3. **闭合监测信息口径。** 题面明确新增点第一次采样时刻、到达延迟、不提供历史或起点读数，并区分名义未来输入与未知实际扰动。真实混合和耗氯参数不直接告知控制器。
4. **修复验证原型的启动错误。** 独立代码复审发现早期闭环原型在监测尚未提供读数时使用了历史水质，虽不立即排放，也会影响后续内部状态。因此未接受早期的因果验收结果，要求修复并重新回放。修订后，独立核查各启动时刻的信息接口和状态更新：前两个决策时刻没有新监测读数；首次合法读数只在到达后用于更新；首次可排放时刻未使用禁用历史。两种基础闭环原型、各三类扰动回放已重新完成容量、预算、时段及信息时序审计，原闭环记录不作为最终证据。
5. **承认阈值事件精度限制。** 空间与时间细化显示平均浓度和总体不足指标的数值变化收缩，但最长连续不足时段对近阈值事件更敏感。补充更细网格后仍不将事件时长描述为精确答案。正式题面已要求报告阈值指标的数值精度及近阈值不确定性。
6. **落实许可与交付。** 原创文件、合成数据、代码的许可分别写入许可文件，脚本具有许可标记；第三方资料只引用，不转载。独立运行附件检查程序通过全部十组检查及十个附件的确定性重生成比较。PDF 为四页 A4，中文文本与任务页版面可读；两遍编译与缺字、溢出检查记录无阻断问题。

数值验证材料已证明各问存在可实现的基础研究路径；受检基础管理方案通过控制与容量约束，模型失配的闭环回放能够完成。反馈并非自动优于固定方案，审查不要求结果必须证明新增监测有效，也不将某一受检方案认定为全局最优。受检高分辨率回放的资源消耗处于常见本科计算设备可承受范围。完整求解实现、拟合参数、用户端结果和策略未收入公开报告。
